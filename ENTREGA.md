## Descripción del proceso

Se creó la estructura inicial del proyecto y se inició el repositorio local con Git, luego se realizó un primer commit con los archivos iniciales, se creó una rama de trabajo para realizar modificaciones en el proyecto, se realizaron cambios en el contenido y los estilos de la página
los cambios de la rama fueron integrados a la rama master mediante merge.
Luego se creó un Issue para proponer una mejora del proyecto. Se realizó un Pull Request con la modificación solicitada y posteriormente se integró a master.
Finalmente, se actualizó el repositorio local mediante git pull.
La rama principal utilizada en este repositorio se denomina master en lugar de main.

## Dificultades encontradas

Al principio me costó un poco entender cómo funcionaban las ramas y cuál era la diferencia entre trabajar en la rama principal y en una rama de cambios. También tuve que prestar atención a no confundir los cambios que hacía. Fui resolviendo estas dificultades revisando los mensajes que mostraba Git y comprobando en cada paso en que rama estaba y si los cambios se habian guardado correctamente.

## Reflexión final

El trabajo me permitió comprender mejor el uso de Git y GitHub para organizar y controlar las diferentes versiones de un proyecto. Aprendi a crear commits, trabajar con ramas, conectar un repositorio local con GitHub, utilizar Issues y Pull Requests y sincronizar los cambios entre el repositorio local y remoto.
